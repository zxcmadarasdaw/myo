# Установка в приложенном оригинале

ZIP содержит коммит [2cce8546](https://github.com/ilyamiro/serpantinum/tree/2cce8546bdb1a72c0fd3bea86c82e6a75464f6c4), указанный в комментарии архива. SHA-256 архива — 5c54673dba8a8dfa222d5a5b95655a8d105cb8ee40242259509b0767f76024af. Исследованы исходники Bash-установщика, адаптеры, зависимости, развёртывание, Nix и PKGBUILD.

| Дистрибутив | Путь в оригинале |
| --- | --- |
| Arch и CachyOS | Общий адаптер pacman для Arch и перечисленных производных. Базовые пакеты и выбранные композиторы проходят через pacman. В некоторых сценариях включается multilib и запускается полное обновление. Отдельные отсутствующие пакеты допускают yay/paru. |
| Fedora и производные | DNF, RPM-алиасы, пакетная установка общих зависимостей, отдельные COPR для недоступных Quickshell и Hyprland, Terra для MangoWC и релизы для некоторых бинарников. Выбор производных идёт по os-release. OSTree и перечисленные EL-системы исключаются. |
| Void | XBPS, отдельные алиасы, внешний репозиторий Hyprland, обновление XBPS перед остальными пакетами и активация служб через runit/elogind. |
| NixOS | Flake для x86_64 и aarch64, пакет, модули NixOS и Home Manager, декларативная конфигурация и отдельные пакеты движков. |

Развёртывание оригинала идёт после зависимостей. Установщик копирует оболочку и профили композиторов, создаёт команды запуска и настраивает выбранные службы. AUR-пакеты имеют отдельные точки входа. Проект сохраняет copyright Illia Miroshnichenko и AGPL-3.0-or-later. Небезопасные параметры оригинального bootstrap, включая отключение GPG-проверки Terra и отдельный refresh pacman перед выборочной установкой, в новую интеграцию не перенесены.

## Изменения механизма пакетов

- Fedora передаёт исходные цели штатному DNF. Он разрешает зависимости, проверяет digest и подпись RPM, обрабатывает ключи настроенных репозиториев, сохраняет нативный кэш и выводит причину отказа. Проверки подписи RPM включены для репозиторных и локальных пакетов.
- Архивы старой пользовательской очереди сохраняются. Fedora может потребовать первую загрузку в собственный кэш DNF. Повтор в нативном кэше использует проверенный RPM.
- Старый этап вызывал rpmkeys до транзакции DNF. Для официального RPM той же версии kitty-0.48.2-1.fc45.x86_64 воспроизведено точное сообщение digests SIGNATURES NOT OK в отдельной пустой базе ключей. Подробный вывод показал NOKEY при правильных дайджестах. Тот же RPM установлен через DNF. Это подтверждает дефект пути проверки. Файл из первого инцидента недоступен для побайтового сравнения.
- Pacman рабочего стола использует системный кэш, конфигурацию доверия, обычные зеркала, CacheServer и нативный downloader. Отдельная искусственная cache-only передача удалена с пути рабочего стола. Режим refresh выполняет согласованную транзакцию -Syu, а текущие базы проверяются перед установкой без refresh. Вместимость Live проверяется до изменений, а полное обновление Live блокируется.
- Параллельность штатной транзакции соответствует 1, 4 или 8. Adaptive корректирует лимит между транзакциями на основе предыдущего результата. Измеряемые события в графическом журнале берутся из нативного вывода. Менеджер обновления ОС сохраняет отдельный поток и свою очередь pacman.
- Проверка результата рабочего стола опирается на состояние пакетной базы, версии Hyprland и Quickshell, конфигурацию оболочки и наличие записи Wayland-сессии. Инструменты OCR и захвата вынесены в расширенные параметры.
