# Serpantinum AI — архитектура

QML отображает настройки, чат и подтверждения. Provider Manager создаёт адаптер по профилю. Model Registry индексирует результат запроса каталога. Сетевые данные проходят через адаптер провайдера. Локальный контроллер AiActions проверяет разрешения и вызывает обработчики действий.

## Контракты

| Компонент | Интерфейс и ответственность |
| --- | --- |
| AI Provider | `probe(profile, deadline)`, `listModels(profile, deadline) → ModelInfo[]`, `chat(ChatRequest, cancel) → ChatEvent stream`. Адаптер отвечает за HTTP, аутентификацию, схему ответа и нормализацию ошибок. |
| Provider Manager | `resolve(profileId) → AI Provider`. Валидирует профиль, собирает адаптер, загружает секрет внутри backend по ссылке на запись. Проверяет доступность провайдера и управляет тайм-аутами. |
| Model Registry | Индексирует снимок каталога с ID, именем и известными метаданными. QML держит кэш для текущего URL, сбрасывает его при смене адреса и отбрасывает ответ предыдущего запроса. Worker перечитывает каталог перед генерацией. Отсутствующая выбранная модель требует явного выбора. |
| Chat Service | `AiChat.send(text)`, `stop()`, `regenerate()`. Использует выбранные модель и активную беседу, маршрутизирует события по ID, ограничивает контекст и обновляет видимый ответ пакетами. |
| Conversation Storage | `history_load`, `history_save`, `history_delete`, `history_clear`. SQLite с транзакциями и версией схемы. Поиск реализован в QML по загруженным сообщениям. При выключенной истории новые сообщения живут в памяти. Очистка отменяет генерацию и отбрасывает поздние события. |
| Permission Manager | `AiActions.prepare(action, conversationId)` проверяет разрешение, цель и снимок состояния. `confirm(token)` поглощает одноразовое предложение. После записи подтверждения повторно проверяются разрешение, состояние и срок. |
| Action Dispatcher | `AiActions.apply(entry, colors)` вызывает фиксированные адаптеры. `requestUndo(recordId, conversationId)` создаёт новое подтверждаемое предложение отката. |

`ChatRequest` несёт ID запроса, модель, роли и текст сообщений, параметры генерации и режим streaming. `ChatEvent` содержит ID, тип `started`, `delta`, `completed`, `cancelled` или `error`. У запроса один конечный результат. `completed` может включать фактическую модель и счётчики токенов. Отменённый ответ явно помечается как прерванный. Ошибки различают недоступность, авторизацию, лимит, тайм-аут и неверный ответ.

## QML и пользовательский процесс

- Этап 2 дополняет модель `GuidePopup` ключом `ai` и ленивой страницей, доступной также через `serpantinum settings ai`. Использовать существующие компоненты настроек, палитру, масштабирование и локализации EN/RU. Создание страницы при обходе поискового индекса оставляет сетевые запросы и чтение секретов действиям пользователя.
- Контракт настроек этапа 2 записан в [AiTab.qml](../../src/quickshell/guide/AiTab.qml). `ai.connection.baseUrl` хранит локальный origin. `ai.generation` содержит `temperature`, `maxTokens` и `streaming`. `ai.privacy.localHistory` содержит согласие на локальную историю. На этапе 3 backend повторно валидирует URL и числовые параметры, даже если их изменили напрямую в файле настроек.
- Этап 3 добавляет Python backend под `src/scripts/ai/` и единый контроллер QML для настроек и будущей панели чата. Запуск через список аргументов `Quickshell.Io.Process`, протокол JSON Lines по stdin/stdout с ID запроса. Worker запускается при первом обращении, принимает отмену параллельно с чтением потока и привязан к жизненному циклу Quickshell. Для сетевого запроса задать тайм-аут подключения, паузы между данными и общий дедлайн. При отмене закрыть поток, при завершении процесса сбросить активные запросы.
- Аргументы процесса, окружение, обычные настройки, stderr и диагностические логи содержат только несекретные данные. Профиль и параметры генерации можно сохранять в `ai.*` через Config. Ключ и личные системные инструкции хранить отдельно от `settings.json` и экспортов, передавать через stdin. Для ключа использовать Secret Service, при недоступности — отдельный пользовательский файл с каталогом `0700`, файлом `0600` и атомарной записью. Привязать ключ к профилю и адресу назначения. При смене адреса запрашивать ключ для нового назначения.
- На этапе 4 держать состояние беседы независимо от ленивого Loader вкладки. Компактная панель освобождает область ввода и фокус при закрытии. Markdown отображать как недоверенный текст, запретить автоматическую загрузку внешних изображений. Для отзывчивости группировать обновления токенов на стороне QML.

## Провайдеры

- Ollama первым работает на loopback, по умолчанию `http://127.0.0.1:11434`. Проверка и обнаружение используют `GET /api/tags`. Пустой список означает, что сервер доступен и локальная модель ещё не установлена. Генерация использует `POST /api/chat` и NDJSON при streaming. Для локального режима использовать локальные модели и отключённые облачные функции Ollama. [Каталог](https://docs.ollama.com/api/tags) · [Чат](https://docs.ollama.com/api/chat) · [Streaming](https://docs.ollama.com/api/streaming) · [Локальный режим](https://docs.ollama.com/faq#how-do-i-disable-ollamas-cloud-features)
- OpenAI-совместимый адаптер проектируется с настраиваемым base URL, реальным каталогом и декларацией поддерживаемых параметров. CoArena служит примером документированных `GET /api/v1/models` и `POST /api/v1/chat/completions`. Его base URL — `https://coarena.ai/api/v1`. Для будущего подключения нужны проверка условий, отдельное согласие на отправку данных и отображение фактической модели ответа. CoArena документирует хранение запросов и ответов и возможность подмены модели при маршрутизации. [Документация CoArena](https://coarena.ai/developers)

## Реализованный протокол этапа 3

Строка запроса содержит уникальный строковый `id` и команду `op`. Сетевые команды принимают `profile: {provider: "ollama", baseUrl}`. Для `probe` и `models` результат `completed` содержит `models`. Для `chat` передаются `model`, `messages` с ролями system, user и assistant и необязательные `options: {temperature, maxTokens, stream}`. Сервер отдаёт `started`, ноль или более событий `delta` с полем `text`, затем один конечный результат. `cancel` передаёт тот же `id`; worker прерывает чтение сетевого ответа. `load_instructions` возвращает поле `text`, `save_instructions` принимает его. Эти команды не обращаются к Ollama.

Чат использует `AiService.generate(messages, options)`, `AiService.cancel(id)` и сигнал `chatEvent(event)`. Текст личных системных инструкций добавляет сам worker. `AiService.selectedModelId` берётся из `ai.connection.model`, где лежат `baseUrl` и `id`.

## Панель, контекст и история этапа 4

[`ChatPopup.qml`](../../src/quickshell/ai/ChatPopup.qml) открывается через существующий хост `Main.qml` и реестр окон под ключом `ai`. При закрытии хост освобождает маску и фокус. Панель не владеет генерацией. Она отображает беседы из [`AiChat.qml`](../../src/quickshell/singletons/system/AiChat.qml).

В запрос идут до 64 последних сообщений в пределах 48 000 символов. Незавершённые ответы исключаются из контекста. У одной беседы есть предел размера, UI предлагает начать новую при его достижении. На диск пишется снимок после отправки и после терминального события. Незавершённый ответ в сохранённом снимке имеет статус «остановлен».

При закрытой панели модели делегатов сообщений и списка бесед пусты. Контроллер продолжает обрабатывать события и воссоздаёт отображение из текущего состояния при повторном открытии. Поток обновляет видимую переписку пакетами с интервалом 45 мс.

SQLite хранится в `$XDG_STATE_HOME/serpantinum/ai/conversations.sqlite3` с резервным корнем `~/.local/state`. Права Linux — `0700` на каталог и `0600` на файл. Чтение пустой истории само по себе не создаёт файл. После включения истории загруженные беседы объединяются с текущими, и текущие сообщения становятся доступными для сохранения. После отключения базу можно очистить явно. Операции сериализуются контроллером, очистка инвалидирует ранее начатую загрузку и очередь сохранений. Markdown рендерится из экранированного текста, без внешних ресурсов.

## Контекст и действия

На этапе 5 [`shell_context.py`](../../src/scripts/ai/shell_context.py) подбирает проверенные справочные фрагменты по последнему пользовательскому сообщению на русском или английском. Worker соединяет справку и пользовательские системные инструкции в одно системное сообщение. Для запроса текущего ОЗУ формируется снимок на основе `MemTotal` и `MemAvailable` — тех же полей Linux, что читает [монитор serpantinum-core](https://github.com/ilyamiro/serpantinum-core/blob/master/src/sysinfo.rs). В Ollama идут только выбранные справочные строки и вычисленные значения, а в QML приходит нетерминальное событие `system_facts` с полем `memory` и статусом `available` или `unavailable`. При включённой истории снимок сохраняется с ответом. Он относится ко времени запроса.

Внешние провайдеры требуют отдельного решения о передаче контекста. Для будущей интеграции показывать пользователю выделенный текст или выдержку лога перед отправкой и давать возможность исключить поля. VPN-ключи и другие секреты исключать из автоматически собираемых данных. Логи считать данными, даже если в них есть текст, похожий на команды.

На этапе 6 worker передаёт модели список предложений при включённом разрешении. Последний блок `serpantinum-action` разбирается только после завершения ответа. В ответе worker приходит объект `actionProposal: {id, target?}` или флаг `actionRejected`. История бесед не содержит токенов подтверждения. Карточка показывает цель и истекает через две минуты. Отдельного доступа к терминалу у модели нет.

| ID | Исполнение |
| --- | --- |
| `open_settings`, `open_wallpaper_hub`, `show_system_info` | Сигнал в действующий маршрутизатор Main.qml, фиксированные панели и вкладки. |
| `launch_app` | Точное совпадение desktop ID или однозначного имени из `DesktopEntries.applications`. Снимок регистрации проверяется снова перед обычным `DesktopEntry.execute()`. |
| `set_theme` | Dracula, Mocha, Nord или Tokyo. Worker читает только соответствующий встроенный JSON. Config применяет поля `activePreset`, `matugen` и `colors`, затем штатный ThemeBackend обновляет оформление. |
| `switch_workspace` | Существующее положительное рабочее пространство текущего монитора Hyprland. Целый номер проходит в фиксированный вызов focus, результат сверяется с текущим состоянием. |

SQLite-файл `$XDG_STATE_HOME/serpantinum/ai/actions.sqlite3` использует тот же приватный каталог, что история. Worker записывает подтверждение до выполнения, затем сохраняет результат. Журнал показывает до 80 последних записей и хранит до 200. Он содержит ID операции, цель, время, результат и признак отката. Снимки для отката живут в памяти сессии. Изменение текущей темы или рабочего пространства после применения делает старый откат недействительным. Снимок темы ограничен полями палитры и не перезаписывает последующие изменения шрифта и других полей.
