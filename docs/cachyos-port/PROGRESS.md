# Этап 1 — аудит совместимости

**Статус** · Завершён 17 ноября 2026 года. База аудита — `a94c92f`. Материалы этапа находятся в `docs/cachyos-port/`. Установка пакетов Serpantinum, изменение служб и правка кода оставлены для следующих этапов.

Проверены shell-установщик и его провайдеры, deploy/update/remove, AUR-рецепты, автозапуск композиторов, QML, Linux/Python helpers, VPN unit/polkit и офлайн-комплект RPM. Сопоставлены имена зависимостей и версии основных пакетов с репозиториями. [Архитектура](ARCHITECTURE.md) · [Матрица несовместимостей](DEPENDENCIES.md)

## Подтверждённые проблемы

1. **Pacman уже подключён, но установка может вмешиваться в систему до проверки необходимости.** `install.sh` и `pm/pacman.sh` содержат `pacman -Sy`, автоматическое раскомментирование multilib, сборку `yay-bin` при отсутствии helper и вызовы AUR с `--noconfirm`. `install_dependencies` вызывает удаление `quickshell-git`, а pacman-провайдер при отказе helper пробует `pacman -Rdd`. Установочный выбор по наличию бинарника выполняется отдельно от проверки `/etc/os-release`. [Bootstrap](../../install/install.sh) · [Провайдер](../../install/modules/pm/pacman.sh) · [Список пакетов](../../install/modules/deps.sh)
2. **Существующая установка поверх пользовательских конфигов требует исправления до применения на готовой системе.** В ветке полной установки копирование backup может завершиться ошибкой, после чего deploy всё равно копирует конфиг и удаляет лишние файлы из каталога композитора. В SDDM удаление `/etc/sddm.conf` возможно после проигнорированной ошибки backup. Shell-установка и AUR могут затрагивать общие для сессий preferences. Обычное обновление некоторых Hyprland-файлов уже сравнивает файл с прошлой поставкой и сохраняет пользовательские правки. [Развёртывание](../../install/modules/deploy.sh) · [Backup](../../install/modules/migrate.sh)
3. **VPN на Arch может сообщить об успехе без рабочего TUN.** В ветке для систем вне Fedora установка unit при ошибке может быть проигнорирована, комплект из checkout пропускается, а без отдельно размещённого комплекта функция возвращает 0. One-click setup проверяет `/usr/bin/dnf5` и запрашивает DNF-пакеты. Сам Linux-движок sing-box 1.14.4 x86_64 уже есть в комплекте. Ветка установки RPM рассчитана на Fedora 45 x86_64. [Установка VPN](../../install/modules/vpn.sh) · [Resolver и setup](../../src/scripts/system/serp_vpn.py) · [Манифест](../../vpn-bundle/manifest.json)
4. **Отдельная ошибка Fedora-ветки VPN.** `serp_vpn_packages.py --terminal install …` обращается к неопределённому `action` в `command(packages, action)`. Вызов с подставными UID и subprocess воспроизвёл `NameError` до запуска менеджера пакетов. Обычная ветка и поток установки офлайн-движка используют другой путь. [Привилегированный helper](../../src/scripts/system/serp_vpn_packages.py#L65)
5. **Lua API зависит от фактической сборки Hyprland.** `canvas.lua` регистрирует `config.unload` с 0.57 и использует `config.reloaded` на старых версиях. Тегированные 0.57.0–0.57.2 содержат событие, 0.56.2 — только post-reload из этой пары. Текущий тест с подставным API проходит обе ветки. Причина прежней ошибки на конкретном компьютере остаётся неизвестной без версии, commit и развернутого файла того сеанса. [Разбор Lua](ARCHITECTURE.md#hyprland-lua-и-ошибка-configunload) · [Upstream изменение](https://github.com/hyprwm/Hyprland/pull/16005)
6. **Есть конкретные Fedora-пути и подсказки в общем runtime.** Hyprland autostart знает только `/usr/libexec/lxqt-policykit-agent`, Arch-пакет размещает его в `/usr/bin`. Дополнительно проверить встроенного агента Quickshell, чтобы исключить две регистрации в одной сессии. В Terminal/Wallpaper Hub/Themess/VPN и части диагностики подсказки называют DNF, RPM Fusion или Fedora-пакеты. [Автозапуск](../../compositors/hyprland/config/autostart.lua) · [Файлы Arch-пакета](https://archlinux.org/packages/extra/x86_64/lxqt-policykit/files/)
7. **Итоговый статус установки покрывает лишь часть готовности.** Проверка локальных типов QML и версии Quickshell полезна для старта. Она не проверяет Linux-загрузку всех Qt-плагинов, графический сеанс, маршрутизацию звука и установку каждого необязательного компонента. `systemctl`-ошибки служб часто скрываются, а отметка версии пишется до итоговой проверки. [Финальная проверка](../../install/modules/verify.sh) · [Запуск служб](../../install/modules/service.sh)

## Точка остановки

Этап 1 завершился перед правками установщика. Предыдущие отчёты, включая текущую работу Wallpaper Hub, находятся на своих местах.

## Этап 2 — общий установщик

- `install.sh` определяет провайдера по `/etc/os-release` до установки Git, проверяет версию Fedora и архитектуру Arch/CachyOS, подтверждает наличие менеджера. Fedora 45 остаётся целевым выпуском. DNF/COPR-ветка и исключение Terra сохранены.
- Pacman устанавливает пакеты настроенных репозиториев одной транзакцией. При синхронизации используется `-Syu --needed`. После успешной синхронизации в том же запуске дополнительные пакеты можно добавить через `-S --needed`. Провайдер сохраняет рабочий `quickshell-git`, повторно опрашивает локальную базу и пропускает установленные зависимости. Базовые пакеты в AUR не ищутся.
- Перед deploy проверяется место. Работает блокировка параллельной установки с тем же каталогом состояния. Прогресс, причины ошибок и путь для повтора записываются в `install.*.log`. Версия отмечается после проверки. Удалённый bootstrap клонирует выбранную ветку в свой временный каталог.
- При замене конфигураций создаётся резервная копия. Пользовательские файлы вне набора поставки, изменённые Hyprland-файлы при обычном обновлении, `settings.json`, существующие обои и настройки Ski/PAM сохраняются. SDDM по умолчанию выключен на Arch/CachyOS. Для переключения существующего display manager нужно явно выбрать замену в меню, пакеты другого менеджера сохраняются.
- 24 проверки установщика прошли, одна Linux-only пропущена. Прогнаны выбор провайдера, нехватка места, отказ транзакции и повтор, отказ backup, настройки и действующий display manager. Дополнительные этапы идут подряд по уточнению пользователя. [Тесты](TESTS.md#этап-2)

## Этап 3 — Hyprland и Quickshell

Canvas восстанавливает окна по сохранённым тегам при `config.reloaded` на всех поддерживаемых версиях Lua-конфигурации, включая Hyprland 0.55–0.57. Установщик проверяет поставляемый Lua-конфиг через реальный `Hyprland --verify-config` перед deploy и установленный конфиг после него. Для Arch добавлен путь обновления стандартного Hyprland. В автозапуске используется встроенный PolkitAgent Quickshell вместо второй Fedora-привязки, а заданная Qt-тема сохраняется. Перед обновлением штатных Lua-файлов применяются правила сравнения и backup из этапа 2.

Файлы пакета Quickshell 0.3.2-1 в Arch Extra содержат импорты Hyprland, Wayland, Networking, Bluetooth, Polkit, Pam, PipeWire, MPRIS, SystemTray и Notifications. Lua, окно/IPC, QML рабочих пространств и регрессии ввода прошли на стендах. Живой Wayland ввод, hotkeys и reload остаются в ручной матрице. [Состав Quickshell](https://archlinux.org/packages/extra/x86_64/quickshell/files/) · [Тесты](TESTS.md#этап-3)

## Этап 4 — мультимедиа

- Arch выбирает `qt6-multimedia-ffmpeg` для новой установки. Уже установленный Qt GStreamer сохраняется, установщик выводит напоминание проверить MP4/WebM на нём. Fedora получает `pactl` из `pulseaudio-utils`, Arch — из `libpulse`.
- Проверка наличия `pw-dump`, `wpctl`, `pactl`, `ffprobe` и декодера H.264 в CLI работает на обеих системах. На способность Qt проиграть файл влияет отдельный плагин. Ошибка активации пользовательских PipeWire units выводится в журнал.
- Сохранены профиль GPU и настройки Steam. Тесты Qt проверили видео, GIF/WebP, Gallery/Cinema, Fastfetch и музыку. AMD Mesa/VA-API, слышимый звук и живой PipeWire остались для целевого сеанса. [Тесты](TESTS.md#этап-4) · [Qt backend Arch](https://archlinux.org/packages/extra/x86_64/qt6-multimedia/) · [PulseAudio utilities Fedora](https://packages.fedoraproject.org/pkgs/pulseaudio/pulseaudio-utils/)

## Этап 5 — VPN

- CachyOS/Arch устанавливает `iproute2`, `nftables`, `polkit` и `python-yaml` из своих репозиториев. `--vpn-only` использует тот же список. Движок устанавливается из локального архива после проверки либо берётся из работоспособного системного sing-box. Fedora сохраняет проверку закреплённого движка и подписанных RPM. Запуск RPM на Arch отсутствует.
- Общая проверка результата читает Proxy/TUN readiness, наличие TUN, права сессии, загруженность unit и его capabilities. Проверка с синтетическим профилем не активирует VPN. Во время активного TUN установщик проверяет уже используемый движок. Arch предлагает запустить терминальный установщик, если пакетов не хватает, чтобы обновление pacman оставалось видимым пользователю.
- Исправлен вызов Fedora helper `--terminal`, ранее давший `NameError`. Дизайн Super+N сохранён. Локальные SHA-256, ELF64 x86-64, права файла и тесты бэкенда прошли. [Тесты](TESTS.md#этап-5)

## Этап 6 — модули и данные

Terminal/Fastfetch показывают подсказку по фактическому дистрибутиву. Themess и Wallpaper Hub сообщают об отсутствующих инструментах или кодеках без Fedora-специфичных команд. Диагностика использует Qt import paths и нативный запрос Qt-пакета. Установщик, лаунчер, QML и updater согласованы по XDG-путям для настроек, состояния и кэша. При наличии только старого `settings.json` или файла версии продолжают использоваться существующие данные.

Widget Fusion/Editor, Canvas, Wallpaper Hub/Collections, Music Studio, Themess и AI проверены соответствующими стендами. Функции используют общие реализации оболочки и не получили отдельных веток CachyOS. Живой Ollama, Linux PTY, сервисы Bluetooth/NetworkManager, tray, реальные уведомления и права PAM остаются в целевой проверке.

## Этап 7 — обслуживание

`install/maintenance.sh` предоставляет `check`, `backup`, `restore` и `uninstall` для shell-установки. Restore сохраняет новый снимок, затем заменяет только присутствующие в выбранном снимке пути. Uninstall архивирует установленные исполняемые файлы и оставляет пользовательские файлы, обои, выбранный display manager и системные пакеты. Регламент обновления и возврата в KDE добавлен в руководство. [Инструкция](../installation/installation.md)

## Этап 8 — регрессии и приёмка

На Windows пройдены доступные автоматические проверки с явными ограничениями по Linux-only сценариям. Полная проверка двух дистрибутивов остаётся открытой, поскольку рабочие Linux-сеансы и установленные WSL-дистрибутивы отсутствовали. Ручной план отделяет подтверждение работы пакетов от сценариев ввода, аудио, маршрутизации и восстановления. [Результаты](TESTS.md#этапы-68) · [Приёмка](NEXT_STEPS.md)
