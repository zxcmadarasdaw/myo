# Прогресс офлайн VPN

## 1. Проверка компонентов

Готово. Проверены четыре файла из voninsll, SHA-256, размер, формат и ELF-архитектура. Результаты в COMPONENTS.md. Оригиналы сохранены. Подписи RPM и запуск ELF проверяются на Fedora. Следующий этап — собрать комплект из проверенного кэша.

## 2. Комплект

Готово. Сборщик добавил корневой vpn-bundle из четырёх проверенных оригиналов и 18 RPM из кэша. Он сверил размеры и SHA-256 всех 22 загрузок. Добавлены SOURCE-метаданные, лицензия движка и бинарные атрибуты Git. dist и исходная папка voninsll остаются локальными. Проверка индекса и чистого клона запланирована на этап 7. Далее — локальная ветка основного установщика.

## 3. Основной установщик

Модуль install/modules/vpn.sh требует локальный комплект на Fedora. Онлайн-ветка установки удалена из основного установщика. Проверка архива и комплекта выполняется перед системной настройкой, устройство TUN подготавливается до установки. install/install.sh получил точку входа для локальной диагностики. Установка из чистого checkout и повторная установка ещё требуют прогона. Далее — выбор движка Proxy и TUN и проверка конфигурации.

## 4. Proxy и TUN

Общий системный движок из комплекта используется по умолчанию. Рабочий путь, явно выбранный для Proxy, сохраняет приоритет. Добавлена проверка версии и хэша установленного файла для локальной переустановки. При подключении движок проверяет адрес testUrl через текущий выход. При неудаче Proxy останавливается или TUN запрашивает остановку службы с существующей очисткой маршрутов. Изменены serp_vpn.py, lock-файл и тестовый имитатор Clash API. Живой трафик и восстановление маршрутов предстоит проверить на Fedora.

## 5. VPN-панель

Существующая панель уже использует режим импорта --local-engine, отображает состояние по данным backend и предлагает bash install/install.sh --vpn-only для ремонта. Теперь эта команда использует комплект Git на Fedora. Компоненты QML не менялись. Следующий шаг — проверка QML с тестовыми ответами.

## 6. Диагностика и восстановление

Добавлена команда bash install/install.sh --vpn-check. Она проверяет комплект, системную версию и SHA-256 движка, проверочные конфиги и авторизацию. components.json показывает наблюдаемые локальные policy rules и DNS-заметки. Диагностика не поднимает туннель и не посылает запрос к VPN-серверу. Команда ремонта использует тот же комплект. Для Fedora Live инструкции в TESTS.md.

## 7. Проверки и передача

Готово на Windows. Набор VPN: 135 тестов, 122 прошли и 13 пропущены по условиям среды. PySide6 проверил действующие QML-компоненты со стабами Quickshell, включая таймауты, локальное восстановление, состояния кнопки, отпускание мыши закрытыми листами и раскладки. Bash проверил синтаксис установщика.

Обычный clone из временного локального Git-репозитория, созданного из подготовленного индекса, получил все 31 файл комплекта. Проверены 30 SHA-256 и режим 100755 установщика. Bash-проверка прошла на целых файлах, отклонила архив с изменённым байтом при том же размере и остановилась до sudo при отсутствии комплекта. Для проверки использовалась временная копия. Назначенная ветка и удалённый репозиторий не изменялись.

В исходниках установки удалена ссылка на RPM-репозиторий SagerNet. Штатный скрипт Fedora работает с комплектом и локальными RPM. Отдельные явные CLI-команды для пользовательской загрузки сохранены.

Следующий шаг — проверить Fedora 45 Live по TESTS.md. Подлежат проверке транзакция DNF и подписи, sing-box check с реальным ELF, разрешения systemd/polkit, Proxy/TUN с пользовательским профилем, TUN-маршруты и DNS, повторный запуск и перезапуск Quickshell. Широкий прогон рабочего стола не выполнялся.
