# Проверка на Fedora 45 x86_64

Проверки на Windows сверяют файлы и моделируют VPN через тестовые процессы. Для подтверждения установки, разрешений и маршрутизации нужен запуск на Fedora 45 под локальным пользователем.

## Установка VPN без сети

1. Склонируй ветку с коммитом комплекта или перенеси чистый клон на USB. Выполни из корня `git ls-files vpn-bundle` и `(cd vpn-bundle && sha256sum -c SHA256SUMS)`.
2. После получения клона отключи сеть локальной Fedora Live. Для варианта с Hyprland/Quickshell сначала подготовь рабочее окружение. Полная установка рабочего стола может требовать сеть.
3. Запусти команду установки. При отсутствии RPM установщик покажет имена пакетов и запустит локальную установку с выключенными репозиториями и проверкой подписей Fedora.
4. Проверь повторный запуск. Сохрани оба лога. При наличии strace можно обернуть команду установки в локальной тестовой сессии трассировкой сетевых вызовов и проверить отсутствие исходящих интернет-соединений при подготовке VPN.

```bash
bash install/install.sh --vpn-only
bash install/install.sh --vpn-check
/usr/local/bin/sing-box version
file /usr/local/bin/sing-box
rpm -q iproute nftables python3-pyyaml
test -c /dev/net/tun
systemctl show serpantinum-vpn.service -p LoadState -p ActiveState -p CapabilityBoundingSet
bash install/install.sh --vpn-only
```

Ожидаются `VPN components: READY`, sing-box 1.14.4, ELF64 x86-64 и загруженная неактивная служба до подключения. По умолчанию логи находятся в `~/.local/state/serpantinum/vpn/components-install.log` и `components.json`. При наличии strace трассировка непривилегированного запуска может ограничивать sudo и polkit. Прогон без сети остаётся основной проверкой автономности.

Для проверки отрицательных сценариев используй отдельную копию checkout и пустой XDG_DATA_HOME. Повреждение архива при сохранении его размера должно дать ошибку SHA-256. Отсутствие каталога комплекта должно дать понятную ошибку до запроса sudo. После возврата исходного комплекта повтори установку.

## Proxy и TUN с сетью

1. Верни сеть, открой **Super+N → VPN**, импортируй собственный профиль и выбери доступный сервер. В Proxy подключись и проверь внешний IP через `curl --proxy socks5h://127.0.0.1:2080 https://ifconfig.me`. После Disconnect локальный порт должен освободиться. Проверь недоступный сервер и восстановление при следующей попытке.
2. Сохрани `ip -4 rule show`, `ip -6 rule show` и, если доступен, `resolvectl status`. В TUN подключись и проверь `ip link show serp-tun0`, DNS и внешний IP через приложение без прокси. Проверь переход Connected после проверки выбранного сервера.
3. Перезапусти Quickshell и снова открой панель. Статус и активный сервер должны совпасть с состоянием службы или Proxy. Разорви соединение и сравни DNS и правила маршрутизации со снимком до подключения. Для сбойного случая проверь Force off и журнал службы `journalctl -u serpantinum-vpn.service -n 50 --no-pager`.
4. Перезагрузи непостоянную Fedora Live, открой тот же клон с внешнего диска и повтори `bash install/install.sh --vpn-only`. Потеря установленных компонентов после перезагрузки Live без сохранения состояния ожидаема.

Проверка по умолчанию использует настроенный `testUrl` через выбранный выход sing-box. Если проверочный HTTPS-адрес блокируется этим выходом, подключение завершится ошибкой. Команда `--vpn-check` проверяет только локальные компоненты.
