# GPU Compatibility Manager — этап 2

Открыть: **Settings → Display → GPU compatibility**. Отдельной программы настроек нет.
Менеджер предназначен для Linux/Wayland. Он запускается после загрузки настроек,
проверяет систему при старте оболочки и по кнопке «Обновить диагностику».

## Что проверяется

- Все обнаруженные DRM-устройства, PCI vendor/device ID, название из `lspci`,
  привязанный драйвер (например, amdgpu, nvidia, nouveau, i915, xe), доступность
  `/dev/dri/*`, состояния подключений и включения KMS-коннекторов.
  AMD/NVIDIA/Intel определяются по vendor ID; неизвестные устройства не скрываются.
  Названия поколений не угадываются по таблице маркетинговых названий.
- Параметр `nvidia_drm.modeset`. Неизвестное значение не считается успешной проверкой.
- Фактический API Qt через GraphicsInfo у панелей, обоев и страницы настроек.
  Переменные окружения показываются отдельно: они не доказывают выбранный API.
  Этот API не сообщает PCI-адрес физической GPU; boot_vga тоже не доказывает,
  на какой карте рендерит Qt. Несколько GPU учитываются раздельно в инвентаризации.
- Состояния и ошибки ShaderEffect. На странице есть зелёная тестовая область,
  использующая существующий rounded_mask.frag.qsb. Статус compiled не является
  проверкой пикселей, FPS или стабильности драйвера.
- Состояния и ошибки MediaPlayer в движке видеообоев. Playing означает начало
  воспроизведения, а не подтверждённые видимые кадры и не аппаратное декодирование.
- Скомпилированные FFmpeg backends/энкодеры. Это кандидаты, а не доказанная поддержка.
  По отдельной кнопке можно проверить локальный MP4/MKV/WebM/MOV: явный VA-API/CUDA,
  явное устройство, обязательный аппаратный формат кадров, до 12 кадров, таймаут
  20 секунд. Отсутствие реально декодированных кадров считается ошибкой.
  Кадры отбрасываются, файл результата не создаётся; сетевые протоколы отключены.
  Результат относится к указанному файлу и FFmpeg, не к декодеру Qt Multimedia.
- Наличие gpu-screen-recorder, wf-recorder и ffmpeg; доступные протоколы захвата
  через wayland-info, если он установлен. Запись автоматически не запускается:
  разрешения, реальный захват и скорость кодирования остаются непроверенными.
- Доступность IPC Hyprland, ошибки его конфигурации, Wayland-сеанс, права на
  устройства, software-override, параметры выбора GPU и декодера.

Отсутствие необязательных `lspci`, `wayland-info`, `ffmpeg`, `hyprctl` отражается
в отчёте; менеджер их не устанавливает. Самому помощнику нужен уже доступный python3.
Команды запускаются аргументами, без shell; предусмотрены таймауты. Никаких
запросов в сеть, телеметрии, modprobe, установки драйверов или правок SDDM/PAM.

## Профили

| Параметр | Performance | Balanced | Ultra |
|---|---|---|---|
| WallpaperBlur / Liquid Glass | Выключены | Включены, если выбраны в теме | Включены, если выбраны в теме |
| Размеры текстур подложек относительно исходных | Эффект не загружается | 65% по каждой стороне | 100% |
| Сила обычного размытия | 0 | 65% | 100% |
| Шейдерные переходы обоев | Обычное затухание | Сохранённый переход | Сохранённый переход |
| Частота процесса аудиоспектра | 20 FPS | 30 FPS | 60 FPS |

При смене профиля процесс спектра перезапускается с новой частотой.
Balanced — начальное значение, без автоматической записи в конфиг. Ultra не
выбирается только из-за названия видеокарты: рекомендации учитывают результаты
проверок, ошибки и фактический renderer. При неизвестной системе рекомендация
остаётся осторожной; никакие цифры производительности не выдумываются.

Все профили сохраняют виджеты и видеообои. Старый переключатель
`general.performance` остаётся отдельной функцией прежнего Serpantinum и может
скрывать виджеты/обои независимо от нового профиля; менеджер его не переключает.

## Безопасное отображение

Включается вручную, через `SERPANTINUM_SAFE_GRAPHICS=1`, при Software/Null renderer
или при обнаруженной ошибке ShaderEffect. Действующий профиль становится
Performance, но выбранный пользователем профиль сохраняется.

Все 35 существующих/добавленных привязок custom QSB отключаются условием политики.
Основные подложки становятся непрозрачными обычными фигурами, Liquid Glass и
размытие не загружаются; обои используют обычное затухание. Флажки, полоса
воспроизведения, заполнения, выделение виджета и спектр имеют простые варианты
без custom shaders. Волны/кольцевой спектр в этом режиме показываются столбиками;
декоративные шейдерные элементы могут отсутствовать. Это не удаляет их настройки.

Видеообои при fallback или ошибке MediaPlayer используют существующий статичный
кадр. Если извлечь его не удалось, показывается сообщение, а путь к видео остаётся
сохранённым. Есть кнопка повторного запуска видео. Если изображения/обои повреждены,
менеджер не может создать из них корректный кадр.

«Сбросить ошибки шейдеров и повторить» снимает защёлку ошибок; повторная ошибка
вновь включает fallback. При восстановлении renderer и отключении ручного режима
возвращается выбранный профиль. Флаг окружения снимается только новым запуском.

Это fallback внутри приложения, а не защита от падения процесса в драйвере или
невозможности создания графического контекста Qt. Обработчик QML не может поймать
такие сбои. Режим Software может иметь ограничения встроенных Qt Effects;
полная работа интерфейса должна быть проверена на целевой системе.

## Смена GPU и сохранение данных

Сравнивается отпечаток упорядоченного набора PCI-адресов + vendor/device ID.
Нумерация cardN и смена версии драйвера не считаются сменой карты. Перестановка
карты в другой PCI-слот считается изменением. Если устройств не обнаружено,
старый отпечаток не перезаписывается.

При первом успешном обнаружении записывается исходный состав. При следующем
изменении показываются уведомление и предупреждение на странице; старое значение
сохраняется до подтверждения пользователем. Например, RX 6600 → RTX 5060 не
сбрасывает настройки. Менеджер пишет только:

```
graphics.profile
graphics.safeMode
graphics.lastHardware
```

Тема, виджеты/композиции, обои, панели, анимации и материалы не мигрируются и не
перезаписываются. Изменяется только действующая политика отрисовки. Отчёт
диагностики и ошибки хранятся в памяти текущего процесса. Системное notify-send
используется для уведомления о смене GPU, сообщения другим людям не отправляются.

Существующий `bin/serpantinumd` на NVIDIA может устанавливать
QT_FFMPEG_DECODING_HW_DEVICE_TYPES=none/vaapi. Эта логика сохранена. Поэтому успешный
отдельный CUDA-тест не означает, что Qt использует CUDA. Значение видно в отчёте.

## Проверки без Linux

Из корня проекта, с уже установленными Python/Node/Qt:

```
python install/tests/gpu_compatibility_test.py
node install/tests/gpu_policy_test.cjs
python install/tests/gpu_qml_test.py
```

Последняя проверка требует PySide6, создаёт реальные QML-объекты менеджера,
страницы и основных fallback-компонентов, но подменяет Quickshell/Config тестовыми
объектами. Она проверяет привязки, восстановление профиля, подтверждение смены GPU,
сохранность остальных настроек и работу флажка в fallback. Это НЕ запуск оболочки
и НЕ проверка Linux IPC, сохранения на диске или графики Wayland.

На Windows 2026-11-12: 10 Python-тестов прошли; Node-проверки политики и smoke-тест
координат/зума холста прошли; Qt integration test прошёл. QML parser успешно
проверил 34 новых/затронутых QML-файла. Отдельно прошёл парсинг 8 файлов этапа 1.
Новых шейдерных бинарников не создавалось; графический тест использует существующий
QSB. qsb-компилятор в локальном комплекте отсутствует. Визуальная корректность не
подтверждена этими проверками.

## План приёмки на Fedora / Hyprland

1. Сохранить конфиг и state, запустить только одну оболочку. Открыть Display → GPU.
2. На RX 6600 сверить модель/PCI/драйвер с lspci -nnk, устройства /dev/dri,
   коннекторы и Qt backend. При отсутствии инструмента ожидать missing/unknown.
3. Проверить зелёный shader preview, Liquid Glass, подложки, переходы, панель,
   Dock, Launcher, виджеты, редактор и штатную блокировку/разблокировку.
4. Переключить три профиля. Проверить исчезновение blur/сложных переходов в
   Performance, изменение детализации Balanced/Ultra и частоты процесса спектра.
   Измерить нагрузку и плавность; заранее FPS не заявляется.
5. Включить безопасную графику. Проверить читаемость и ввод, флажки, полосу
   воспроизведения, выделение/перемещение виджетов, спектр, статичный кадр видео.
   Отключить: выбранная тема и профиль должны восстановиться.
6. В тестовой копии подменить один shader URL на несуществующий. Ожидать ошибку,
   fallback и сохранение настроек. Вернуть URL, сбросить ошибки, проверить повтор.
7. Проверить несколько локальных H.264/HEVC/AV1-файлов через VA-API/CUDA на явно
   выбранном устройстве; отдельно проверить воспроизведение Qt. Повреждённый файл
   должен дать ошибку, а не passed. Проверить отказ по таймауту.
8. Сделать короткую запись штатным recorder. Проверить файл, звук, несколько
   мониторов и кодек. Наличие инструмента/энкодера само по себе недостаточно.
9. Проверить реальную замену AMD → NVIDIA: уведомление, новый драйвер/modeset,
   сохранность всех настроек, CUDA/Qt decoding и переход обратно. Отдельно проверить
   Intel (i915/xe), nouveau и систему с несколькими GPU при наличии оборудования.
10. Перезапустить оболочку: profile/safeMode/принятый отпечаток должны сохраниться.
    Проверить битый JSON helper, отсутствие python3, отсутствие DRM и инструментов.
11. Повторить функции этапа 1 на двух мониторах: pan/zoom/home, поиск/миникарта,
    группы, композиции, привязки, перезапуск и смена разрешения. Окна приложений
    должны по-прежнему управляться Hyprland.

## Обратимый пробный запуск на Linux

Предполагается, что обычный Serpantinum и его зависимости уже работают. Это не
установка Fedora/Hyprland/драйверов. Копию этого проекта перенести на Linux отдельно
от установленной версии, без Windows-папки .tools. Оригинальную установку сохранить.

Перед тестом сохранить `~/.config/serpantinum` и `~/.local/state/serpantinum`
в отдельный каталог с датой, например через `cp -a`. Оболочка использует обычные
пользовательские настройки: источник scripts/caching.sh переопределяет QS_SETTINGS,
поэтому одного произвольного QS_SETTINGS недостаточно для полной изоляции.

Остановить действующий экземпляр его обычным способом; для запуска через daemon
предусмотрена команда `serpantinumd stop`. Проверить, что автозапуск/сервис не
поднимает второй экземпляр. Затем в терминале, в корне тестовой копии:

```bash
SERPANTINUM_DIR="$PWD/src" bash ./bin/serpantinumd start --verbose
```

Для начального упрощённого отображения:

```bash
SERPANTINUM_SAFE_GRAPHICS=1 SERPANTINUM_DIR="$PWD/src" bash ./bin/serpantinumd start --verbose
```

Для возврата остановить тестовую оболочку и запустить сохранённую установленную
версию прежним способом. Установщик в этом процессе не запускается; автозапуск,
SDDM и системная аутентификация не меняются. При необходимости вернуть резервные
копии пользовательского конфига/state после остановки оболочки.

В Windows оригиналы всех изменённых существующих файлов сохранены в
`.backup/gpu-stage2-original/` с прежней структурой. Их можно скопировать поверх
одноимённых файлов для отката исходников именно к состоянию до этапа 2. Это
состояние уже включает ранее написанный этап 1; оно не является чистым upstream.
Добавленные GPU-файлы при таком откате не используются прежними qmldir/Shell.
Не применять этот откат поверх более поздних собственных изменений без сравнения.

## Справочные API

- [Qt GraphicsInfo](https://doc.qt.io/qt-6/qml-qtquick-graphicsinfo.html): информация
  относится к окну, с которым связан Item, а не к windowless singleton.
- [Quickshell Process](https://quickshell.org/docs/v0.2.1/types/Quickshell.Io/Process/):
  запуск помощника и сбор ответа через StdioCollector.
