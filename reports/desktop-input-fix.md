# Исправление ввода рабочего стола — 14 ноября 2026

Рабочая копия: `E:\Serpantinum`. Исходный commit: `7fef490da1b750baba2855feeef5a297d478e8ca`.
Отчёт подготовлен при локальной проверке исправления. Установленная Fedora в этой сессии не обновлялась.

**Найдены и воспроизведены дефекты QML, способные оставлять прозрачную поверхность с активным вводом и зависшее состояние редактора. Точная причина первоначального случая пользователя не установлена:** нет журнала того события и доступа к его сеансу Fedora 45 / Hyprland 0.57.1 / Quickshell 0.3.2. Связь с предшествовавшим зависанием также не доказана.

## Подтверждённые причины в коде

1. **`Main.qml` + `guide/GuidePopup.qml`: закрытие → повторное открытие до конца анимации.**
   Main меняет generation и отменяет таймер закрытия, но не отменял `closeSequence` уже видимого кешированного Guide. Повторная запись `visible = true` не вызывает `onVisibleChanged`. Старая анимация доводит `introBase` до 0, её callback игнорируется из-за устаревшего generation. Окно остаётся открытым и принимает ввод. Тест исходного кода получил `visible=true, alpha=0, input=true` после быстрого повторного открытия.
   Дополнительно, после прерывания exit-анимации и срабатывания страховочного таймера в Guide оставался старый `exitCallback`; последующее закрытие кнопкой могло вызвать именно его и оставить прозрачное окно.

2. **`widgets/WidgetRedactor.qml`: освобождался неправильный монитор.**
   `close()` очищал `targetMonitorName` до деактивации Loader. Привязка `monitorName` успевала переключиться на экран по умолчанию; `Component.onDestruction` отправлял `setRedactMode(false)` уже для другого экрана. `WidgetLoader` прежнего монитора сохранял `isRedacting=true` и скрывал обычные виджеты. При переводе открытого редактора между мониторами прежний экран также не освобождался. Включение редактирования было связано с отложенным callback загрузки layout, а не с жизненным циклом редактора.

3. **`Main.qml`: бесконечный повтор загрузки ошибочного компонента.**
   `executeSwitch()` повторял неудачное создание через `Qt.callLater` без ограничения, даже при `Component.Error`. Это подтверждённый источник повторных ошибок и нагрузки, но не доказанная причина сообщённого зависания. Теперь ошибка компонента завершает запрос; ожидание размера/загрузки ограничено 40 попытками через Timer 50 мс.

## Исправление и изменённые файлы

| Файл относительно `src/quickshell` | Изменение |
|---|---|
| `Main.qml` | Ввод и фокус зависят от логического состояния открытия; при закрытии mask становится пустым, анимация продолжается. Отмена устаревшего exit при повторном открытии. Ограничение повторов загрузки. Диагностика `[input]`. |

| `calendar/Dashboard.qml` | То же для календаря. |

Добавлены `install/tests/desktop_input_qml_test.py` и этот отчёт.

Используется документированный `QsWindow.mask: Region`, а не предположение, что прозрачность или `MouseArea.enabled=false` передают события нижнему Wayland-окну. Пустая Region с `Combine` не принимает ввод; `Xor` инвертирует область относительно всего окна, поэтому при закрытии меняются и `item`, и `intersection`. См. [Quickshell 0.3: QsWindow.mask](https://quickshell.org/docs/v0.3.0/types/Quickshell/QsWindow/) и [LayerShell keyboardFocus](https://quickshell.org/docs/v0.3.0/types/Quickshell.Wayland/WlrLayershell/). Документация ветки 0.3 проверена; бинарник 0.3.2 здесь не запускался.

## Что проверить на Fedora

Сначала записать `quickshell --version`, `hyprctl version`, `hyprctl -j layers` и `serpantinum logs 200`.

1. После запуска: ПКМ по пустому столу, клики по виджетам, клики и прокрутка в обычном приложении.
2. Super+H → закрыть кнопкой, Escape и Super+H; повторить быстро во время входной/выходной анимации, в том числе 20 раз подряд. Рабочий стол должен оставаться кликабельным, повторно открытые настройки — видимыми.
3. Войти в Edit Mode: drag, resize, групповое выделение, отмена drag при переключении окна/рабочего пространства, выход Escape. Проверить сохранённую геометрию.
4. Во время редактирования открыть Super+H, затем сразу закрыть настройки. Проверить, что редактор завершён и обычные виджеты вернулись.
5. Повторить на втором мониторе, перевести открытый редактор между мониторами. Проверить оба экрана после закрытия. Проверить изменение разрешения/scale и отключение монитора.
6. Переключать workspace с открытыми/закрывающимися настройками, редактором и терминалом. Проверить мышь и клавиатуру в обычных приложениях после каждого перехода.
7. Process Explorer: открыть/закрыть во время анимации, кликнуть на рабочий стол после закрытия. Повторить для launcher, clipboard и calendar.
8. Terminal: получить фокус кликом, набрать команду, перейти в обычное приложение, открыть настройки/редактор, вернуться. Невидимый терминал не должен удерживать клавиатуру.
9. Music drawer / Audio Studio, File Dock, Network, Themess, Wallpaper Hub: клики, открытие/закрытие; проверить обычное приложение под прозрачными полями.
10. GIF/видео/погода: переключать и прерывать переходы, запускать/останавливать воспроизведение; проверить Canvas pan/zoom и виджеты после завершения переходов.
11. `serpantinum restart`, затем повторить шаги 1–4. Закрытые окна не должны оставлять активных областей ввода. Наличие mapped-слоя само по себе не доказывает захват: учитывать mask и состояние контроллера.

## Как установить локальное исправление

Использовать копию репозитория с этим исправлением либо перенести архив исправления на Fedora и распаковать его в отдельную папку. Выполнять команды **из корня обновлённого репозитория или распакованной папки**, где есть `src/quickshell/Main.qml`. Для стандартной установки этой же версии:

```bash
set -e
installed_src="${SERPANTINUM_DIR:-$HOME/.local/share/serpantinum/src}"
test -f "$installed_src/quickshell/Shell.qml"
test -f src/quickshell/Main.qml
backup_dir="$installed_src/quickshell.before-input-fix-$(date +%Y%m%d-%H%M%S)"
cp -a "$installed_src/quickshell" "$backup_dir"
for rel in Main.qml Shell.qml guide/GuidePopup.qml widgets/WidgetRedactor.qml \
  widgets/Widget.qml launcher/Launcher.qml clipboard/Clipboard.qml \
  calendar/Dashboard.qml processexplorer/ProcessExplorer.qml; do
  cp "src/quickshell/$rel" "$installed_src/quickshell/$rel"
done
serpantinum restart
printf 'Резервная копия QML: %s\n' "$backup_dir"
```

Если установленная версия уже отличается или эти файлы изменены вручную, сначала сравнить их с патчем `desktop-input-fix.patch`; не заменять пользовательские изменения вслепую. Настройки, темы, раскладки и compositor-конфиги команды выше не меняют. Для отката скопировать те же девять файлов из `backup_dir` обратно и перезапустить Serpantinum.

## Восстановление мыши при повторении

Из доступного терминала сначала сохранить сведения, затем закрыть панели штатным IPC:

```bash
serpantinum logs 200 > "$HOME/serpantinum-input.log"
hyprctl -j layers > "$HOME/serpantinum-input-layers.json"
serpantinum ipc redactor close
serpantinum ipc main handleCommand close '' ''
serpantinum ipc main handleCommand close processes ''
serpantinum ipc main handleCommand close launcher ''
serpantinum ipc main handleCommand close clipboard ''
```

Если главный поток не отвечает на IPC, прервать ожидающую команду Ctrl+C и выполнить `serpantinum restart`. Перезапускается оболочка Serpantinum, не Hyprland. Это прервёт встроенные терминальные сеансы, поэтому при возможности сначала завершить/сохранить их работу. После перезапуска повторно проверить клики и сохранить журнал. Для дальнейшей диагностики нужны время/действие перед сбоем, состояние двух мониторов и строки `[input]`, `ReferenceError`, `TypeError`, `Widget component failed to load`. Не удалять пользовательские настройки и раскладки ради восстановления.
